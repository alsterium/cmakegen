# T015 Research — GitHub Actions self-host matrix

- Date: 2026-08-09
- Question: How should the CI workflow express required operating-system and
  compiler coverage and portable runner-shell behavior?

## Primary sources

- [GitHub Actions matrix documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/run-job-variations)
  documents `strategy.matrix.include` for explicitly enumerated job variants.
- [GitHub Actions workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)
  documents matrix failure behavior and `fail-fast`.
- [GitHub Actions variables documentation](https://docs.github.com/en/actions/concepts/workflows-and-actions/variables)
  documents workflow and step environment variables.
- [GitHub Actions runner documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job)
  documents the hosted runner labels and matrix use for multi-machine jobs.

## Conclusion and implementation impact

The workflow uses an explicit `include` matrix: GCC/Linux, AppleClang/macOS,
and MSVC/Windows provide the required platforms, while Clang/Linux supplies
practical compiler diversity. `fail-fast: false` preserves failures from all
platforms in one run.

Each matrix entry performs stages A through E from the self-host specification.
It finds both executables by filename after the build, rather than assuming a
single-config output layout; this covers Visual Studio's configuration
subdirectory on Windows. The normal configuration receives the discovered
stage-0 executable so CTest runs both the bootstrap-source-drift and
bootstrap/normal-equivalence checks.

The workflow intentionally uses a cold `FetchContent` population for every
job. The earlier source-only cache did not encompass the dependency state that
CMake actually reuses, so it added complexity without a reliable performance
benefit. Re-populating dependencies keeps every matrix run self-contained and
does not make a cache service part of the CI correctness path.

Remaining uncertainty: hosted image toolchain revisions change over time. The
workflow reports its selected compiler and CMake versions in every job, making
an image regression diagnosable without weakening the C++23 requirement.
